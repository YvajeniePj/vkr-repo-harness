# Методология формирования бенчмарка и экспериментов

## 1. Задачи Типа А: Миграция на Python
Цель: взять существующий репозиторий с развитыми тестами на исходном языке и переписать его на Python с сохранением 100% поведения.

### Градация по размерам:
1. **Категория S (< 5,000 LOC)**:
   - Примеры кандидатов:
     - JS парсеры: `marked`, `markdown-it`, `json5`
     - Утилиты: `glob`, `minimatch`, `chalk`
   - Особенности: компактная кодовая база, эталонный набор unit-тестов, легко верифицировать дифференциальным тестированием.
2. **Категория M (5,000 – 50,000 LOC)**:
   - Примеры кандидатов:
     - `httpie` (Go/Rust аналоги), `ripgrep` (подмодули парсинга регулярных выражений), CLI-утилиты на Go/Node.js.
   - Особенности: разветвленная структура модулей, внешние зависимости, асинхронный ввод/вывод.
3. **Категория L (> 50,000 LOC)**:
   - Примеры кандидатов:
     - Крупные сервисы (веб-фреймворки, ETL-инструменты).
   - Особенности: требует многоуровневой декомпозиции и оркестрации субагентов.

## 2. Задачи Типа Б: Слияние репозиториев (Repository Synthesis)
Цель: объединить функционал двух независимых репозиториев в единый согласованный продукт на Python.

### Эталонные пары:
1. **Пара 1 (Демонстрационная)**: `n8n` (workflow automation) + `ComfyUI` (node-based generative execution)
   - Целевой продукт: Python-сервис автоматизации рабочих процессов, где ноды ComfyUI нативно встроены в DAG-оркестратор сценариев.
2. **Пара 2**: REST API фреймворк + Event-driven Message Broker Worker (например, слияние FastAPI + Celery/RabbitMQ паттернов).
3. **Пара 3**: CLI Data Processing + Interactive Visualization Engine.

### Спецификация приёмки:
- Для каждой пары заранее фиксируется $N$ бизнес-сценариев.
- На каждый сценарий создается автоматический E2E-тест (HTTP-запрос, CLI-вызов или WebSocket-сообщение).

## 3. Условия честного сравнительного эксперимента
1. **Единая модель**: Одинаковая версия LLM (например, `gpt-4o-2024-08-06` или `gemini-1.5-pro-002`) во всех сравниваемых системах.
2. **Прокси-учёт**: Все запросы проходят через LiteLLM Proxy с фиксацией точных объемов токенов и цен.
3. **Zero-Human-in-the-Loop**: Никаких подсказок в процессе генерации.
4. **Повторяемость**: Каждая конфигурация запускается $\ge 3$ раз.
