# Спецификация ключевых компонентов Repo-Harness

## 1. Sandbox (Локальная песочница)
- **Изоляция**: Выделенный каталог сессии. Поддержка Linux cgroups, WSL2, Docker-контейнеризации.
- **Безопасность**:
  - Whitelist бинарников: `python`, `pytest`, `git`, `tree-sitter`, `ruff`, `pip` и др.
  - Блокировка опасных команд (`rm -rf /`, `curl | sh`, попытки модификации `/etc`, системных каталогов).
  - Контроль путей: разрешение всех относительных путей относительно корня песочницы, нормализация `os.path.realpath`, запрет разыменования symlink за пределы рабочей папки.
- **Ограничения ресурсов**: memory limit (например, 4GB), process count limit (max 16 pid), execution timeout (например, 120s на команду).
- **Audit Logging**: Структурированный лог (JSONL) всех вызванных команд, stdout, stderr, exit_code, CPU/RAM usage.

## 2. GitHub Read-Only интеграция
- Входные данные: Personal Access Token (PAT) пользователя с минимальным скоупом `repo:read`.
- Принцип безопасности: токен никогда не передаётся в LLM context и не попадает в переменные окружения песочницы.
- Клонирование/скачивание выполняется отдельным доверенным хост-скриптом.
- Блокировка push-запросов на уровне сетевых правил и прав токена.

## 3. Tree Analyzer (AST-парсер и компактное дерево)
- **Файловая фильтрация**:
  - Игнорирование тяжелых директорий: `.git`, `node_modules`, `venv`, `__pycache__`, `dist`, `build`.
  - Сжатие директорий с датасетами и ассетами: сворачивание 10 000 картинок в строку `[assets/images: 10,240 files (.png, .jpg)]`.
- **AST-анализ (Tree-sitter)**:
  - Парсинг исходного кода на поддерживаемых языках (JS/TS, Go, Rust, Python, C/C++).
  - Построение графа символов (классы, функции, интерфейсы, типы, экспорты, импорты).
  - Определение точек входа (entry points) и графа вызовов (call graph).

## 4. Context Manager (Управление контекстом и кэшированием)
- **Динамическая загрузка/выгрузка (Eviction Policy)**: Загрузка файлов по требованию субагента, удаление из активного контекста после завершения подзадачи.
- **Мультимодальность**: Поддержка текстового кода, диаграмм/скриншотов (PNG/JPEG), документации (PDF, Markdown).
- **Сводки (Repo Maps & Summaries)**: Использование сжатых карт зависимостей вместо сырых файлов.
- **Сжатие истории**: Семантическая суммаризация предыдущих шагов агента при приближении к порогу контекста (например, >75% контекстного окна).
- **Интеграция с Context Caching**: Сохранение неизменяемого системного промпта и дерева файлов в кэше LLM для снижения стоимости в 2–4 раза.

## 5. Оркестратор и иерархия субагентов
- **Модель ролей**:
  - `Root Orchestrator`: декомпозиция цели, планирование майлстоунов, мониторинг бюджета токенов.
  - `Architect Agent`: проектирование целевой модульной структуры на Python.
  - `Porting/Synthesis Subagents`: реализация конкретных модулей и функций.
  - `Verification Agent`: запуск тестов, проверка покрытия, сопоставление со спецификацией.
- **Конфликт-резолюшн**: Контроль пересекающихся правок через dependency graph и пошаговое применение патчей.

## 6. Multi-tier LLM Routing
- **Level 1 (Frontier Models)**:
  - Назначение: высокоуровневое планирование, дизайн архитектуры, разбор сложных комплексных ошибок.
  - Модели: GPT-4o, Claude 3.5 Sonnet, Gemini 1.5/2.0 Pro.
- **Level 2 (Utility/Fast Models)**:
  - Назначение: генерация шаблонного кода, форматирование, суммаризация, точечный search/replace.
  - Модели: Gemini 1.5/2.0 Flash, Claude 3.5 Haiku, GPT-4o-mini, локальные Qwen2.5-Coder.
- **Метрика маршрутизации**: Сопоставление качества выполнения (K3) и суммарных расходов (K4) в сравнении с режимом "только Frontier".

## 7. Patch Engine vs Git
- **Движок Search/Replace**:
  - Точный поиск блока строк в файле и замена на новый блок.
  - Преимущество: минимальный контекст, простота валидации.
  - Риск: ненайденный блок при изменении соседних строк.
- **Git-ориентированный движок**:
  - Использование `git diff`, `git apply`, веток и атомарных коммитов на каждый шаг.
  - Преимущество: нативная поддержка трехстороннего слияния (3-way merge), тривиальный откат через `git reset`.
  - Риск: хрупкость формата unified diff при генерации LLM.
- **Задача этапа 3**: Экспериментальное измерение процента неприменимых правок и оверхеда токенов для обоих подходов.

## 8. Чат-интерфейс на Vue
- SPA на Vue 3 + Tailwind CSS + Pinia.
- Отображение:
  - Интерактивный диалог с агентом.
  - Дерево репозитория в реальном времени.
  - Панель трассировки и логирования шагов субагентов (Action Trace Viewer).
  - Метрики расхода токенов и стоимости текущей сессии в реальном времени.
  - Drag-and-drop загрузка zip-архивов и файлов.
