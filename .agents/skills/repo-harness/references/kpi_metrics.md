# Справочник метрик эффективности (KPI K1–K9)

В рамках проекта Repo-Harness оценка качества строится строго на объективных, воспроизводимых и измеримых метриках без субъективного участия человека.

## K1. Успешный запуск (Clean Installation & Health Check)
- **Формула**:
  $$K1 = \frac{N_{\text{passed}}}{N_{\text{total}}}$$
- **Методика**: Результат генерации разворачивается в чистом изолированном Docker-контейнере одной стандартной командой (`docker build` / `pip install -e .` / `python -m app`). Проверяется запуск приложения и прохождение базового health check за фиксированный тайм-аут (например, 60 секунд).

## K2. Функциональная полнота (Functional Completeness)
- **Портирование (Тип А)**:
  $$K2_{\text{port}} = \alpha \cdot \frac{T_{\text{passed\_ported}}}{T_{\text{total\_ported}}} + (1-\alpha) \cdot \frac{D_{\text{passed\_diff}}}{D_{\text{total\_diff}}}$$
  где первое слагаемое — доля успешно пройденных портированных тестов исходного проекта, а второе — дифференциальное тестирование (одинаковый набор входных данных подаётся в исходный проект и в портированный проект на Python; сравнивается идентичность выходных структур).
- **Слияние (Тип Б)**:
  $$K2_{\text{merge}} = \frac{F_{\text{passed\_e2e}}}{F_{\text{spec\_total}}}$$
  где $F_{\text{spec\_total}}$ — фиксированное число целевых сквозных функций объединённого продукта, покрытых E2E-тестами.

## K3. Интегральный успех задачи (Task Success)
Бинарный флаг успеха:
$$K3 = \begin{cases} 1, & \text{если } K1 = 1 \text{ и } K2 \ge 90\% \\ 0, & \text{иначе} \end{cases}$$

## K4. Стоимость (Cost Efficiency)
- Средняя стоимость запуска:
  $$\overline{C} = \frac{1}{N} \sum_{i=1}^N C_i$$
- Стоимость одной успешной задачи:
  $$C_{\text{success}} = \frac{\sum_{i=1}^N C_i}{\sum_{i=1}^N K3_i}$$
Все цены рассчитываются через LiteLLM Proxy по официальным тарифам провайдеров на дату фиксации эксперимента.

## K5. Расход токенов (Token Consumption)
- Детализация по категориям:
  - $T_{\text{input}}$ (входные токены)
  - $T_{\text{output}}$ (сгенерированные токены)
  - $T_{\text{cache}}$ (кэшированные токены / Context Caching)
- Нормализованная метрика: токены на 1000 строк кода исходного репозитория (Tokens / kLOC).

## K6. Временные затраты и шаги (Wall-clock Time & Steps)
- Общее время выполнения (в секундах/минутах).
- Общее число шагов агентов и вызовов внешних тулов до остановки.

## K7. Автономность (Agentic Autonomy)
- Количество зацикливаний, таймаутов, превышений лимита шагов.
- Доля запусков, завершившихся штатно без вмешательства оператора.

## K8. Надёжность системы правок (Patch Reliability)
- Patch Application Rate: Доля успешно применившихся правок без синтаксических сбоев.
- Clean Rollback Rate: Доля успешных откатов при падении тестов.
- Regression Rate: Доля правок, сломавших ранее зелёные тесты.

## K9. Стабильность и дисперсия (Stability & Variance)
- Стандартное отклонение ($\sigma$) для K3 и K4.
- 95% доверительный интервал (bootstrap, $B=1000$) между 3+ независимыми прогонами для каждой задачи.
